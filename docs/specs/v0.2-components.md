# Spec: v0.2 - Components

- Status: **accepted** (decisions confirmed by the maintainer on 2026-11-13)
- Milestone: [v0.2](https://github.com/maximcuynat/open-logic/milestone/2)
- Date: 2026-11-13

## Goal

Turn the wire editor into a circuit editor: place a NAND gate, an input
switch and an output LED, connect their pins with wires, and compute which
pins are electrically connected (nets). No simulation yet (v0.3), but the
netlist built here is exactly what the simulator will consume.

## Out of scope

Simulation and signal colours (v0.3), more built-in gates (v0.3), subcircuits
(v0.4), multi-selection, copy/paste and buses (v0.5).

## 1. Core model (`src/core/`, pure, TDD)

### 1.1 Component types

A `ComponentType` is static data, registered once in `ComponentLibrary`:

| Field | Meaning |
|---|---|
| `id` | Stable string used in files: `nand`, `switch`, `led` |
| `body` | `Rect2i` in cells, relative to the anchor, unrotated (facing right) |
| `pins` | Ordered list of `PinSpec { name, direction (IN/OUT), offset: Vector2i }` |
| `label` | Text drawn on the body |

The library is **data-driven**: adding a gate later (NOT, AND, OR, NOR, XOR,
XNOR, buffer...) means registering a new `ComponentType`, with no change to the
editor, the netlist or the file format. Gates are drawn as labelled rectangles
(maintainer decision), which works for any gate.

Footprints (unrotated, anchor at `(0, 0)`, one cell = 16 px):

```
NAND (2x4)            SWITCH (2x2)        LED (2x2)

 A ─┬────┐               ┌────┐                ┌────┐
    │NAND├── Y           │ SW ├── Y        A ──┤LED │
 B ─┴────┘               └────┘                └────┘
```

| Type | Body (x0, y0) to (x1, y1) | Pins |
|---|---|---|
| `nand` | (-1, -2) to (1, 2) | A in (-2, -1), B in (-2, 1), Y out (2, 0) |
| `switch` | (-1, -1) to (1, 1) | Y out (2, 0) |
| `led` | (-1, -1) to (1, 1) | A in (-2, 0) |

Pins sit one cell outside the body; a short stub joins them to the body.
Pins are always on integer cells, so wires snap to them naturally.

### 1.2 Component instances

`Component` (immutable value object, like `WireSegment`):

- `id: int` - unique within a circuit, never reused during a session, persisted
- `type_id: String`
- `position: Vector2i` - anchor cell
- `rotation: int` - quarter turns clockwise, 0..3
- `props: Dictionary` - per-type state; `switch` has `{"on": bool}`

Derived (computed, tested): `pin_cells()`, `body_rect()` (rotated),
`occupied_cells()`. Rotation maps an offset `(x, y)` to `(-y, x)` per quarter turn.

### 1.3 Circuit

`Circuit` gains components next to wires:

- `add_component`, `remove_component`, `replace_component` (move, rotate,
  toggle are replacements of an immutable value), `get_components`,
  `find_component_at(point)`.
- `next_component_id()` - monotonic counter, restored from files as `max(id) + 1`.
- **Placement rule:** a component body may not overlap another body, and a pin
  may not sit inside another body. `can_place(component)` reports it; the
  editor shows an invalid placement ghost in red and refuses the click.
- Wires may cross bodies (no restriction in v0.2).

### 1.4 Commands (undoable)

`CircuitCommands` gains `place_component`, `remove_component`,
`move_component`, `rotate_component`, `toggle_switch`. Each is one undo step,
**including the wire changes below**. Removing a component keeps its wires
(they become dangling).

### 1.4.1 Wires follow moved and rotated components

Maintainer decision: wires stay attached when a component moves or rotates.
`WireFollower.reattach(circuit, before: Component, after: Component)` is a
pure function returning `{remove: [WireSegment], add: [WireSegment]}`:

- Only segments with an **endpoint on a pin** of the component are affected;
  the rest of each wire is untouched.
- Segment `Q -> P` (P on the pin) becomes the L route `Q -> P'`, where `P'` is
  the pin's new cell. The leg arriving at the pin is aligned with the pin's
  facing: horizontal for pins facing left/right, vertical for up/down.
- A segment with both endpoints on pins of the moved component is translated
  as a whole.
- Degenerate routes (`Q == P'`) remove the segment; duplicates are skipped.

While dragging, the editor previews the rerouted wires live and commits move
and wires as a single undo step on release.

### 1.5 Connectivity (`Netlist`)

A `NetlistBuilder` computes nets from a circuit; the editor rebuilds it on
every `changed` signal (cheap at this scale, optimised in v0.6).

Connection rules:

| Situation | Connected? |
|---|---|
| Two wires share an endpoint | yes |
| A wire endpoint lies on the interior of another wire (T junction) | yes |
| Two wires cross (interior over interior) | **no** |
| Collinear wires overlap | yes |
| A wire endpoint lies on a pin cell | yes |
| A wire passes over a pin cell without ending there | no |
| Two pins on the same cell (touching components) | yes |

Algorithm: union-find over "connection points" (wire endpoints and pin cells);
each wire is unioned with every connection point lying on it.

Output `Netlist`: a list of `Net { wires, pins: [(component_id, pin_name)] }`
plus diagnostics used by the editor and later by the simulator:

- `driver_count(net)`: number of OUT pins; more than one = **conflict**.
- Floating net: no OUT pin.

### 1.6 File format schema 2

```json
{
  "format": "open-logic",
  "schema": 2,
  "wires": [{ "a": [0, 0], "b": [4, 0] }],
  "components": [
    { "id": 1, "type": "nand", "at": [6, 0], "rot": 0 },
    { "id": 2, "type": "switch", "at": [-4, 0], "rot": 0, "props": { "on": false } }
  ]
}
```

- Readers accept schema 1 (migrated: no components) and 2; writers always write 2.
- Strict validation as today: unknown type, duplicate id, bad rotation,
  overlapping bodies or invalid props reject the whole file.

## 2. Editor (`src/editor/`)

### 2.1 Tools and palette

A narrow **component palette** docked on the left (deep dark, square buttons,
sharp corners) lists the tools; every tool also has a menu entry and shortcut:

| Tool | Shortcut | Behaviour |
|---|---|---|
| Select | `V` | Click selects a wire or component; drag a component to move it (attached wires follow) |
| Wire | `W` | As today |
| NAND | `1` | Ghost follows the cursor, `R` rotates, click places |
| Switch | `2` | Same |
| LED | `3` | Same |

With a component selected: `R` rotates it, `Backspace`/`Delete` removes it.
Double-clicking a switch toggles it (stored and saved; it has a visible effect
from v0.3 on).

### 2.2 Rendering (same visual language as v0.1)

- Body: filled rectangle (`Palette.COMPONENT_BODY`), 1 px border
  (`Palette.COMPONENT_BORDER`), centred label in `UI_TEXT_DIM`. Selected:
  orange border. Invalid ghost: red border; valid ghost: translucent is **not**
  allowed (opaque rule), so ghosts use a dedicated opaque dim palette.
- Pin stub: wire-width rectangle from body edge to pin cell. Unconnected pins
  in grey, connected pins in wire blue.
- Junction marker: a **square** (2x wire width) where three or more wire ends
  meet or at a T junction, so connections are explicit. No round shapes.
- Hover on a pin while drawing a wire: pin highlighted (snap feedback).

## 3. Implementation order (each step: failing tests first, then code)

1. `ComponentType`, `ComponentLibrary`, `Component` (rotation, pins, body)
2. `Circuit` components API and placement rule
3. `WireFollower` (straight and L reroutes, both pin facings, both ends on
   the component, degenerate route, untouched far segments), then
   `CircuitCommands` component commands using it
4. `NetlistBuilder` (one test per row of the connection table, plus conflict
   and floating diagnostics)
5. `CircuitSerializer` schema 2 and schema 1 migration
6. Editor: palette, placement tool, select/move/rotate/delete, toggle
7. Rendering: bodies, pins, junction squares, ghosts; palette colours added
8. Docs: `FILE_FORMAT.md` schema 2, `ARCHITECTURE.md`, screenshot

Mapping to the v0.2 issues: component model (1-2), NAND/switch/LED (1, 6, 7),
place/move/rotate/delete (3, 6), connectivity (4, 7), file format (5).

## 4. Verification

- `make check` green; every rule of section 1.5 covered by a test.
- Round trip: save a circuit with every component type and rotation, reload,
  compare.
- A schema 1 file from v0.1 still opens.
- Manual checklist (maintainer): place, rotate, move, delete each type; wire a
  switch to both NAND inputs and the NAND to a LED; check pin colours and

## 5. Decisions (confirmed 2026-11-13)

| Topic | Decision |
|---|---|
| Gate symbol | Labelled rectangle with sharp corners; more gates to come |
| Moving a component | Attached wires follow (section 1.4.1) |
